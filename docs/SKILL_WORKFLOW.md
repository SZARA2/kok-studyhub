# 통합 봇의 담당 스킬 업데이트

사용자는 `콕 통합` 하나에 요청합니다. 1~3번 학습 기능은 수집 스킬이 만든 `lecture.md`를 사용하고, 4번 일정은 사용자가 올린 시간표만으로도 실행합니다. 기능 구현과 웹 생성은 Grok Bot 스킬이 맡습니다.

## 담당 파일

- 인수: `grok-skills/skills/kok-lecture-collector/SKILL.md` — 링크·파일·직접 준 강의 내용을 수집해 출처와 누락을 표시한 `lecture.md` 생성.
- 용철: `grok-skills/skills/kok-problem-drill/SKILL.md` — 1번 단계별 문제 풀이.
- 용철: `grok-skills/skills/kok-podcast/SKILL.md` — 2번 NotebookLM 대화형 오디오.
- 용철: `grok-skills/skills/kok-concept-lab/SKILL.md` — 3번 3D 시각화 설명.
- 용철: `grok-skills/skills/kok-schedule/SKILL.md` — 4번 시간표와 복습 일정 화면.
- 공통 검토: `grok-skills/skills/kok-router/SKILL.md`, `grok-skills/skills/kok-onboarding/SKILL.md` — 번호 연결, 공통 입력, 시작 안내와 업데이트 절차.
- 제무: 이후 누코드 입력 스킬을 담당합니다. 이번 묶음에는 물리 장치 연결 구현이나 검증을 포함하지 않습니다.

## 업데이트 순서

1. 사용자가 개선 의견이나 수정 문서를 봇에 전달하고 대상 기능을 지정합니다. 봇은 담당 스킬과 관련 리소스의 변경 범위를 정합니다.
2. 현재 버전을 백업하고 **앱의 수정 가능한 팀용 스킬과 리소스를 실제로 수정**합니다. 버전·변경 이력·필요한 도구도 함께 고칩니다. 대화로 수정하겠다고 답한 것만으로 완료 처리하지 않습니다.
3. 저장된 스킬 이름·버전·본문을 다시 읽어 확인합니다. 같은 샘플로 바뀐 기능을 실행하고, 공통 수집이나 라우터 변경 시 관련 기능의 연결도 확인합니다. 일정은 강의 자료 없는 시간표 입력도 검사합니다.
4. 검증 결과와 남은 제한을 기록하고, 사용자가 공유를 요청한 경우 최신 스킬로 공유 템플릿을 갱신합니다. 다른 계정의 기존 사본이 자동 갱신된다고 가정하지 않습니다.
5. 팀이 GitHub로 협업할 때는 담당 폴더와 리소스·변경 이력을 함께 수정해 Fork/PR 또는 쓰기 권한이 있는 브랜치로 제출합니다. 공개 저장소의 직접 push에는 쓰기 권한이 필요합니다.
6. 검토한 고정 커밋을 앱에 반영하는 경로도 지원합니다. GitHub는 선택적인 소스 검토·백업 경로이며 실시간 동기화나 실행의 필수 조건이 아닙니다.

## 함께 지킬 입력과 결과 규칙

- 수집 결과의 공통 입력은 `lecture.md`입니다. 각 자료의 출처·위치·범위·확인 상태를 유지합니다.
- 원문 사실과 제공 정답, Bot 설명과 변형 문제를 구분합니다. 못 읽은 부분에서 출제하지 않습니다.
- 원문에 없는 날짜를 확정 마감으로 만들지 않습니다. 복습 제안과 테스트용 가상 일정은 따로 표시합니다.
- 일정은 먼저 시간표를 요청합니다. 모호한 과목명·종료 시간은 확인 필요로 남기고, 학기 기간·마감 날짜를 추정하지 않습니다. 시간표와 강의 자료의 과목이 다르면 연결되지 않은 상태로 둡니다.
- 팟캐스트는 실제 음원 파일 또는 재생 가능한 결과를 확인합니다. 대본만 만든 상태와 구분합니다.
- 웹 메뉴 이동과 봇의 새로운 생성 실행을 구분합니다. 공유 템플릿에는 강의 원문 파일·개인 일정·로그인·키를 넣지 않습니다.
